# 微脑智能协同系统

面向中小企业的智能经营与业务财务协同系统。员工照常办事，系统把客户、合同、项目、费用、资金和账务收成同一套事实；需要判断时，AI 把事实整理成能追溯、能行动的经营结论。

微脑要缩短的，是「业务发生」到「老板看清并采取行动」之间的距离。

**20 人以下的企业可以免费使用。** 免费的是使用权，不是源码。微脑不是开源项目，不提供源码下载、自行分发或二次开源。企业规模按在册使用人数计，20 人以下即可申请免费使用；达到或超过 20 人，或需要私有化部署、实施陪跑和持续服务，请通过官网联系重庆锐戍信息技术有限责任公司，按合作方式约定。

## 产品由什么组成

三部分一起工作，缺一不可。

1. **Web 工作台**保存正式业务。组织权限、客户、合同、交付、任务、审批、报销、票据、资金、凭证、账簿、报表、人事、薪酬和税务准备都在这里执行规则、控制权限、留下审计。
2. **飞书与企业微信**把高频动作送到员工已经在用的地方。文字、图片和文件可以发起业务、补充材料、查询进度和接收提醒。复杂管理仍回到工作台。
3. **AI 能力层**负责听懂、看懂、问清、串联、解释和总结。正式审批、付款、入账、结账、调薪和申报仍由业务规则、权限和责任人完成。

一条业务的走向是：

`员工表达或提交材料 → AI 理解并补齐信息 → 正式流程执行 → 财务事实沉淀 → 经营结果汇总 → 风险和行动回到相关人员`

飞书、企微、Web 和 AI 使用同一份后台事实。渠道会话和模型记忆不能另写一套客户、审批或账。模型超时或不可用时，规则、模板和工作台仍然可以办事。

## 它解决什么问题

中小企业每天都在产生信息，老板要答案时却经常要等人重新整理：

- 客户谈到哪一步，要等销售回查聊天记录。
- 合同签了多少、该收多少、实际到了多少，几张表对不上。
- 项目是否延期、会不会影响验收和回款，往往出了问题才知道。
- 费用为什么突然增加，要财务重新拉表解释。
- 账上有利润，现金为什么仍然紧张，业务和财务各说各的。
- 哪张票据、哪个审批、哪笔记账卡住了运行，只能逐个问人。

根因是事实散落在聊天、表格、纸质单据和彼此不通的系统里。业务发生之后，还要人再录入、再核对、再汇总。微脑让这件事在发生时就进入正确的业务链。

## 优势

**在员工已经习惯的地方办事。** 飞书或企业微信里可以直接说「帮我报销昨天的打车费，发票在附件里」「这是新签的服务合同，帮我建档并识别付款节点」「查一下本月还有哪些回款没到」。系统识别意图、提取已知信息，缺什么再问什么。先发需求后补发票，或先发合同再补客户名称，都留在同一个办理过程里。

**AI 做理解，人和规则做裁决。** AI 承担六类工作：听懂要办什么，看懂发票、回单、合同和截图，问清当前最缺的一项信息，把客户、合同、项目、票据和凭证放回同一条链，把异常说成管理者能看懂的话，并在正式事实之上形成经营摘要。它不直接同意或驳回，不直接付款或认领流水，不把识别结果写成正式凭证，不改合同核心金额，不替代工资、五险一金和税务的正式计算。

**每个重要数字都能回到原业务。** 合同计划、结算事项、票据与回单、会计确认、账簿和报表分层管理。签了合同不等于确认了收入，客户说付了款不等于系统已经核销，开了发票不等于利润已经入账。销售、交付和财务围绕同一业务对象协同。

**便利不换失控。** 查询和工具调用继承当前员工的真实身份、角色和数据范围。未绑定渠道身份或没有权限时默认拒绝。审批、付款、核销、过账、结账、调薪和税务相关动作有专门权限、状态规则和人工确认。操作者、审批轨迹、资料变化和 AI 调用用途都留痕。合同金额、预计回款、观察口径和法定报表分开标识，避免把计划当成结果、把推测当成正式账。

**可以先闭环，再扩大。** 企业按一个高频场景上线，跑通发起、审批、执行和财务结果，再接入渠道、补齐财务证据链，最后再扩大经营摘要和主动提醒。模型可以按用途配置云端、自带凭据或本地路线。

## 带来的价值

**老板**不用等某个人临时整理汇报。客户、合同、项目、回款、费用和利润可以放在一起看。异常带有影响对象、金额和建议动作，结论能回到原单据和责任人。可以按随时查询、每日简报、每周复盘、每月体检四个节奏看公司：现金和待办现在怎样，昨天发生了什么，本周哪些事项会影响回款，这个月收入、成本、利润、应收应付和结账质量如何变化。

**财务**少做收集、改名、录入和来回找单。票据和合同先由 AI 分类、抽取字段，并保留原件、识别结果和修改记录。银行流水、结算事项、报销、发票和回单放在同一条链里给出匹配候选；金额、日期或对象对不上时交给人工复核。凭证草稿来自业务事实和科目映射，正式凭证仍经复核与过账，已记账结果不能被静默改写。月结前，未处理业务、缺票、未核销资金和凭证异常按优先级集中列出。向老板解释费用或利润变化时，有统一口径和证据链。税务准备保留系统值、调整值和最终申报值，辅助材料不表示已经完成税局申报。

**业务负责人**能看见自己这段工作的下游。销售能看到合同、交付和回款的关系，项目负责人能看到延期对验收和资金的影响，审批人除了申请表还能看到材料是否齐全、有哪些风险提示。任务和告警挂在业务对象上，减少口头催办。

**员工**少填表、少切换系统、少重复说明。常见业务用自然语言发起，图片和文件进入当前流程，系统只追问缺失项，正式提交前给出摘要确认，进度可以随时查。

上线后可以用这些指标看值不值：资料到归档的时长、票据字段人工修正率、流水匹配命中率、凭证从资料齐全到复核完成的时长、月结阻断时长，以及老板问经营情况时还要财务临时拉表的次数。

## 功能简介

| 领域 | 能做什么 |
|------|----------|
| 组织、权限与登录 | 企业档案、部门、岗位、员工、角色和数据范围；登录会话、强制改密、产品授权。菜单和操作随当前账号权限变化 |
| 客户与销售 | 客户档案、联系人、跟进、关怀提醒；渠道里可新建客户、记跟进、查进度 |
| 合同与履约 | 合同主档、不可变版本、审核申请、智能抽取、风险提示、付款节点和结算事项。审核通过不自动产生收付款或凭证 |
| 交付项目 | 以客户为锚的项目、成员、里程碑、进展和资料，并与任务、费用弱关联 |
| 协同 | 任务、可配置审批、告警、催办和订阅。审批完成不等于付款或入账完成 |
| 行政与人事 | 用章、请假、出差、采购申请；日报；入职、离职、调薪、考勤。请假类型会影响工资计薪 |
| 费用 | 报销、对公费用、备用金、固定资产。业务页维护申请和审批，实际收付进入财务处理 |
| 薪酬与个人税务辅助 | 工资批次、五险一金、个税代扣台账和辅助申报文件。辅助文件不代表已向税局申报 |
| 资金与财务处理 | 资金账户、银行流水、回单、收付确认、应收应付核销、凭证草稿 |
| 会计、报表与期间 | 凭证复核和过账，总账、明细账、日记账，资产负债表、利润表、现金流量表，损益结转、月结年结和归档 |
| 税务准备 | 增值税、企业所得税等申报包工作台，区分系统值、调整值和最终申报值，支持小规模与一般纳税人口径 |
| 渠道与 AI | 飞书、企业微信的自然语言和附件入口；票据识别、合同分析、会计建议、经营摘要；模型与识别服务可配置、可降级 |
| 审计 | 日志中心统一查询访问、业务变更和 AI 链路，详情脱敏，在线保留 180 天 |

技术上由三部分组成：Go 业务后端负责规则、权限、财务、报表和审计；Vue 3 Web 工作台负责人机界面；Python AI 服务负责渠道接入、文档识别、多轮补参和受控工具调用。业务数据在 PostgreSQL，附件进受控对象存储。每套部署服务一个企业。

## 适用企业与产品边界

适合这些企业：老板要亲自掌握经营，但没有时间逐个部门追问；人员不多，客户、合同、项目和财务数据已经分散；没有专职信息化团队；日常工作主要在飞书或企业微信；财务人数有限，希望少做整理、匹配和反复解释；要求权限、审计和财务责任清楚。

以下不在当前产品承诺内：

- 直接连接税务局完成在线申报。
- 无需人工确认的自动付款、自动过账、自动结账或自动审批。
- 用对话完全替代正式业务工作台。
- 在缺少可靠业务数据时凭模型生成经营结论。
- 用 AI 替代老板、审批人或专业财务人员承担责任。

## 建议的落地顺序

1. 先统一企业主体、部门、岗位、员工、审批关系和财务期间，保证每笔业务都知道谁发起、谁负责、谁有权处理。
2. 选报销、合同收付款、客户跟进或项目交付中的一个高频场景，从发起到财务结果走通。
3. 把员工高频、低风险的提交和查询放到飞书或企业微信。
4. 把票据、流水、资金事项、凭证、账簿、报表和税务准备接到同一条证据链。
5. 基础数据稳定后，再扩大经营概览、周报、月报和异常提醒。

企业得到的是三种能力：看得清，业务、资金、财务和风险有统一事实；管得住，每个流程有权限、有责任、有证据；动得快，重要变化及时出现，结论能够变成下一步行动。
